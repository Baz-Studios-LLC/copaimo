The user repeatedly insists that every change to CRASHOUT (the office-survival game at `C:\Users\jsull\Desktop\crashout\index.html`) preserve gameplay balance.

**Why:** They care that the game stays fair and skill-expressive. ⚠️ **DESIGN PIVOT 2026-06-29:** survival is **no longer time-bounded** — it used to be "an unbounded quadratic creep guarantees every run ends ~7–12 min," but the user changed this so a *focused* player can keep a run going **indefinitely** (still harder over time, but NOT a sure loss). See the bottom entry. New content must not break the new model: keep the *unavoidable* pressure (passive creep) bounded/saturating below sustained relief, and keep the *avoidable* pressure (backlog) as the escalating threat.

**How to apply:** After any change touching the meter (rate/creep/crunch), relief (break room/pills/coffee cart), spawn rates, office events, outfit/modifier multipliers, or new encounters, sanity-check the impact — ideally a quick deterministic sim of meter dynamics (`tick(dt)` + pinned `dayTime`, measure rise vs relief) — and report the balance implication. **New target (post-pivot):** focused play (tasks kept clear + break room worked) sustains indefinitely; an inattentive player still burns out fast; difficulty keeps rising then plateaus. The ease-difficulty lever is the *inflow* (event/task rate), never slowing the meter rise or buffing relief (see [[crashout-balance-lever]]). Watch `payMul` stacking (clamped at 2.0 combined outfit×modifier). The historical dated entries below predate the pivot — their "quadratic guarantees runs end / ~7-min ceiling" framing is superseded.
