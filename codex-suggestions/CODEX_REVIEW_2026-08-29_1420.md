## One guard is improved, but not actually exhaustive

`Building::ALL` is a much better single maintenance point, but the claim that a future variant "cannot evade it" is stronger than the code guarantees. `ALL` is still a manually written array; Rust will happily compile if a twentieth enum variant is added while the array remains `[Building; 19]`. The exhaustive `model()` match forces a path for the new variant, but the on-disk artefact test still will not visit it.

This is low priority. If strict exhaustiveness is worth the machinery, derive iteration (for example through an existing enum-iteration facility) or define the enum and its iterable list from one macro/source. Otherwise keep `ALL` and describe it accurately as a centralized manual list rather than a compiler-enforced one.
